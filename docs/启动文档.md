# JobUWant 启动文档

本文档记录当前 Windows PowerShell + WSL2 Ubuntu + UNC 项目路径环境下，JobUWant Web App 的可靠启动方式。

项目路径：

```text
/home/votally/projects/JobUWant
```

Windows UNC 路径：

```text
\\wsl.localhost\Ubuntu\home\votally\projects\JobUWant
```

## 目标服务

- Backend: `http://127.0.0.1:8000`
- Frontend: `http://127.0.0.1:3000/tasks`

## 推荐启动顺序

### 1. 启动后端

在 Windows PowerShell 中执行：

```powershell
wsl.exe -e bash -lc "cd /home/votally/projects/JobUWant/webapp/backend && nohup env PYTHONPATH=. /home/votally/projects/JobUWant/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 > /tmp/jobuwant-backend.log 2>&1 < /dev/null & sleep 2; ps -ef | grep uvicorn | grep -v grep || true; ls -l /tmp/jobuwant-backend.log 2>/dev/null || true"
```

验证：

```powershell
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/api/health" -TimeoutSec 10
```

期望结果：

- HTTP 状态码为 `200`
- 响应里包含 `jobuwant-web-api` 和 `status":"ok"`

后端日志：

```powershell
wsl.exe -e bash -lc "tail -n 80 /tmp/jobuwant-backend.log"
```

### 2. 启动前端

当前环境下，优先使用已有构建产物的生产预览方式，不优先使用 `next dev`。

在 Windows PowerShell 中执行：

```powershell
$cmd = 'pushd \\wsl.localhost\Ubuntu\home\votally\projects\JobUWant\webapp\frontend && "C:\Program Files\nodejs\node.exe" node_modules\next\dist\bin\next start --hostname 0.0.0.0 --port 3000 > C:\tmp\jobuwant-frontend-win.log 2>&1'
Start-Process -FilePath "cmd.exe" -ArgumentList @("/c", $cmd) -WindowStyle Hidden
```

等待数秒后验证：

```powershell
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:3000/tasks" -TimeoutSec 30
```

期望结果：

- HTTP 状态码为 `200`

前端日志：

```powershell
Get-Content -LiteralPath "C:\tmp\jobuwant-frontend-win.log" -Tail 120
```

## 为什么不用默认前端开发命令

在本机环境中，WSL 内的 `npm` 可能指向 Windows npm：

```text
/mnt/c/Program Files/nodejs/npm
```

这会让 Next.js 在 UNC 路径或映射盘路径下运行，容易出现目录监听异常，表现为服务显示 `Ready` 但 Windows 侧访问 `http://127.0.0.1:3000/tasks` 失败。

本次验证中，最稳定的方式是：

- 后端：WSL venv 里的 `uvicorn`
- 前端：Windows `node.exe` 直接运行 Next.js 的 `next start`

## 最终验证命令

```powershell
try {
  $backend = Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8000/api/health" -TimeoutSec 10
  "BACKEND $($backend.StatusCode) $($backend.Content)"
} catch {
  "BACKEND_ERROR $($_.Exception.Message)"
}

try {
  $frontend = Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:3000/tasks" -TimeoutSec 30
  "FRONTEND $($frontend.StatusCode)"
} catch {
  "FRONTEND_ERROR $($_.Exception.Message)"
}

Get-NetTCPConnection -LocalPort 8000,3000 -State Listen -ErrorAction SilentlyContinue |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

本次成功结果：

```text
BACKEND 200
FRONTEND 200

127.0.0.1:8000
0.0.0.0:3000
```

## 注意事项

- 启动服务不等于开始新的岗位信息收集。
- 不要调用模型相关阶段，除非用户明确同意。
- `/tasks` 当前实际实现里，主按钮会创建任务并立即开始岗位信息收集。继续调整按钮和跳转逻辑前，应先确认产品决策。

## 2026-08-08 验证过的启动方式

本节是重启电脑后再次验证可用的启动方式。优先按本节执行。

执行方式：在 Windows PowerShell 中使用 wsl.exe -e bash -lc 加下面的命令主体。

后端命令主体：
cd /home/votally/projects/JobUWant/webapp/backend && : > /tmp/jobuwant-backend.log && setsid -f env PYTHONPATH=. /home/votally/projects/JobUWant/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 > /tmp/jobuwant-backend.log 2>&1

前端命令主体：
cd /home/votally/projects/JobUWant/webapp/frontend && : > /tmp/jobuwant-frontend.log && setsid -f env PATH=/home/votally/projects/JobUWant/webapp/.tools/node/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin npm run start -- --hostname 0.0.0.0 --port 3000 > /tmp/jobuwant-frontend.log 2>&1

验证命令主体：
curl -sS --max-time 10 http://127.0.0.1:8000/api/health
curl -sS --max-time 30 http://127.0.0.1:3000/tasks | head -c 200

成功标准：
- 后端响应包含 jobuwant-web-api 和 status ok。
- 前端响应以 <!DOCTYPE html> 开头。
- 进程列表包含 uvicorn 和 next-server。

说明：
- setsid -f 用于让服务进程在当前 PowerShell 调 WSL 命令结束后继续运行。
- 前端命令显式指定 /home/votally/projects/JobUWant/webapp/.tools/node/bin，避免误用 Windows npm。
- 启动服务不等于开始新的岗位信息收集，也不会调用模型相关阶段。


进程验证命令主体：
ps -ef | grep uvicorn | grep -v grep || true
ps -ef | grep next-server | grep -v grep || true
